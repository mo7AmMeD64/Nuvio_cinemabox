# F10 — P2P / torrent playback (#171): status

Branch `f10-p2p`, off integration `50afbae3`. Off by default (`AJ_P2P_LIGADO`,
"Servidor P2P (experimental)"). Automatic source selection never picks P2P;
only a torrent chosen by hand in the Sources sheet goes through it.

## What the slice does

With P2P on and **no server address**, a build that carries the engine plays
the chosen torrent itself: `p2p_resolver` -> `p2pmotor_resolver` starts the
embedded engine, adds the magnet (addon trackers, public fallback trackers),
waits for metadata, picks the file (addon fileIdx > SxxEyy > largest video),
prepares a stream, proves the first 64 KB through the engine's
`http://127.0.0.1:<port>/stream/...` with N01 `rede_pedir` (streamed discard,
cancellable), and hands that local URL to the player. With an address, the
old route (Stremio streaming server on the LAN, `p2p.c`) is unchanged.

Engine: **nuvio-engine 0.1.3** (github.com/NuvioMedia/nuvio-engine, commit
`02938d7`, which is upstream HEAD on 2026-10-04) on libtorrent 2.0.12.

Lifecycle (`src/p2pmotor.c`), the PLANO F10 rules:

- One short mutex; never held across metadata waits, the first-bytes probe,
  statvfs, the folder walk, or engine create/destroy.
- `p2pmotor_cancelar()` only bumps a generation. A new choice in the Sources
  sheet, closing the player and app exit cancel; the request returns
  `P2P_ERR_CANCELADO` within one 20 ms poll and never publishes a URL.
- Engine events are matched by `request_id`/`torrent_id`; late ADDED/METADATA/
  PREPARED from an older request are dropped and counted.
- Disk: engine soft cap `min(512 MB, free/4)`; **hard cap** on the real blocks
  in `<data>/p2p`: `min(1536 MB, free/2)` measured at start. Refuse to start
  under 256 MB free. RAM: engine memory cache 16 MB, hard stop above 32 MB.
- statvfs failure = refuse (`P2P_ERR_DISCO`), at start and in the watchdog.
- Watchdog is its own thread (every 2 s): folder size, free space (stops below
  128 MB free), engine RAM, ENOSPC error events. The UI thread only reads an
  atomic (`p2pmotor_motivo_parada`) and shows why playback stopped.
- Stop: detached thread waits until every user of the engine pointer has
  released it, joins the watchdog, destroys the engine (writers stop), and
  only then deletes `<data>/p2p`. App exit waits up to 1.5 s; if destroy is
  still running the folder is left and the next start (no engine alive)
  deletes it.
- One torrent at a time; the engine URL is never stored in the source list.

UI: Settings › Contas e serviços › P2P. With the engine, the toggle's help
text says the device downloads **and shares** while playing, the disk limit,
that everything is deleted when the player closes, and the legal risk. "Testar"
shows `motor desta TV · versão 0.1.3 · <hard cap> MB` (statvfs on the test
thread). Without the engine and without an address it says
`sem motor neste pacote · informe o endereço`. Errors: no peers, no video,
engine did not start, not enough space (256 MB), free space not measurable,
memory limit, storage filled during playback. 14 strings in all 28 tables
(9 reused from `agente/p2p2`, 5 new); `tools/idiomas.py` passes.

## Licences / toolchains

- nuvio-engine: **GPL-3.0-or-later**. The app is GPL-3.0 (LICENSE), so
  static linking is compatible. The notices ship in every package that can
  carry the engine: `deploy/app/licencas/` (`p2p-avisos.txt` plus the full
  texts of libtorrent BSD-3, try_signal, Boost BSL-1.0, OpenSSL Apache-2.0 and
  the engine's GPL-3.0). They reach the LG `.ipk` (the whole `deploy/app`),
  the APK (`assets/licencas/`, `tools/android.sh`) and the Samsung `.tpk`
  (`res/licencas/`, `tools/tpk.sh`); the build scripts abort without
  `p2p-avisos.txt` in the finished package.
- libtorrent 2.0.12 BSD-3, Boost 1.86 BSL-1.0, OpenSSL 3.5.7 (Android/Mac,
  engine's pinned build) / 3.4.1 (webOS sysroot, LG and TPK) Apache-2.0.
- Android: NDK 27.2 with `-fexperimental-library` + `c++experimental`
  (the engine uses `std::jthread`; it pins NDK 29), cmake >= 3.24.
  The libs used here are from `/Volumes/ExternalSSD/tmp-arquivo/nv-p2p2-motor-android`,
  built from the same commit `02938d7`.
- LG / TPK: `tools/p2p-motor/build-arm.sh` / `build-tpk.sh` in the
  `nuvio-webos-sdk` docker image (`-j3`; higher -j gets OOM-killed). The TPK
  image itself (gcc 8.3) cannot compile the C++20 engine.
- Size: `libmain.so` +10.4 MB (arm64) / +7.0 MB (armv7) uncompressed vs the
  `50afbae3` APK; `libnuvio_engine.so` for TPK 5.6 MB stripped.

## Release builds ship the engine (owner decision, 1.8)

`tools/p2p-motor/pasta.sh` finds the engine root: `$NUVIO_P2P_MOTOR`, else
`~/.nuvio-p2p-motor`, else `/Volumes/ExternalSSD/nuvio-p2p-motor`.
`NUVIO_P2P_MOTOR=none` builds without the engine on purpose (a warning is
printed). Layout: `<root>/android`, `<root>/arm` (LG), `<root>/tpk`,
`<root>/mac` (tests), `<root>/licenses`. A root that exists but misses a
library of the platform being built aborts with exit 2. `tools/android.sh`,
`tools/arm.sh` and `tools/tpk.sh` use it automatically, so
`release-android.sh`, `arm.sh --ipk` and `release-samsung.sh` ship the engine
and check the finished package for it (APK: the `Nuvio Engine/` marker string (API symbols are hidden) in both
`libmain.so`; `.ipk`: inside the packaged `nuvio-proto`; `.tpk` 6+:
`lib/libnuvio_engine.so`; the 4/5 `.tpk` and its auto-update `.so` are
rebuilt without `-DNV_P2P_MOTOR` and must not carry it).
